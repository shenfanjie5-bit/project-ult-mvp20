## Cheap classify: 18 fields should not be normal LLM calls

All `cheap_classify` fields are event-status classification, not generative analysis. The normal path should be:

1. Compute dependency fingerprint over the governed sources.
2. If unchanged, preserve existing `Inactive`/`Known`.
3. If changed, run high-precision keyword/pattern policies.
4. Return `Inactive` when no concrete event is present; return `Unknown` only when source rows are missing or malformed.
5. Use LLM/human review only for ambiguous/conflicting packets, not for every stock.

Important nuance: existing `scripts/audit_a_share_event_text_preclassification_screen.py` is conservative by design; its tests assert direct Known writes are not allowed from keyword hits alone. That means no-hit packets can become deterministic `Inactive`, but hit packets should remain review-gated until a stricter classifier is approved.

In the full run, 15/18 `cheap_classify` fields had available non-LLM candidates across the universe. The remaining 3 were not parser failures: `L8.shock.black_swan`, `L9.industry.data_price`, and `L9.macro.geo` are intentionally review-gated before writing `Known`. `L9.company.product_order` is mostly deterministic (`1,629/1,646`) with 17 gated packets.

## Implementation priority

1. Convert all 18 `cheap_classify` fields to deterministic event-policy drafts with fingerprint gating.
2. Promote the existing `script_fill.py` annual-report parsers into the LLM fill workflow for the 3 already-supported fields.
3. Add formula/parser extractors for the 15 score-impacting local fields in the parser/formula/proxy group.
4. Treat `web_analysis` as connector work, not prompt work; until source connectors exist, keep these out of automatic high-confidence filling.
5. Keep the 10-stock, 100-stock, and full-universe comparison harness in CI/manual audit, and only keep LLM for fields where the non-LLM candidate fails on coverage, schema, or semantic agreement.
